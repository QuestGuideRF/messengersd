# MessengerSD

MessengerSD - это веб-мессенджер на чистом PHP + MySQL, рассчитанный на обычный shared hosting без WebSocket, Node.js и отдельного VPS. Обновление данных сделано через AJAX/polling, поэтому проект можно развернуть даже на недорогом хостинге с Apache/PHP/MySQL.

Проект уже включает:

- личные чаты;
- базовые групповые чаты;
- PIN-авторизацию по username;
- вложения и безопасную отдачу файлов;
- реакции, ответы, черновики, архив, закрепы;
- список активных сессий;
- отдельный чат "Сохранённые" для заметок самому себе;
- отдельный механизм "сохранить сообщение" из диалога в избранное;
- светлую, тёмную и системную тему.

## 1. Основные возможности

### Авторизация

- Вход по `username + 4-значный PIN`.
- Если username новый, пользователь создаётся при первом входе.
- PIN хранится через `password_hash`, а не в открытом виде.
- После 5 неверных попыток PIN вход временно блокируется на 5 минут.
- PIN можно изменить из профиля.

### Личные чаты

- отправка и получение сообщений;
- статусы `unread/read`;
- отметки "отправлено / прочитано";
- редактирование сообщений;
- удаление "только у меня" и "у всех";
- reply / цитирование;
- реакции;
- поиск по сообщениям внутри чата;
- черновики;
- блокировка пользователя;
- архивирование чатов;
- закрепление чатов;
- сохранение отдельных сообщений в избранное.

### Вложения

- загрузка файлов до 50 МБ на сообщение;
- поддержка изображений;
- миниатюры изображений, если доступно расширение GD;
- безопасная отдача файлов через `download.php`;
- прямой доступ к PHP-скриптам внутри `uploads/` запрещён.

### "Сохранённые"

В проекте есть два разных механизма, и это важно:

1. `saved_messages`
   Это сохранение конкретных сообщений из обычных диалогов в избранное.

2. `saved_chat_messages`
   Это отдельный чат "Сохранённые" / "Saved Messages", куда пользователь пишет сам себе.

Сейчас основная страница self-chat:

- `saved_chat.php`

Совместимость со старыми ссылками сохранена:

- `saved.php` -> редирект на `saved_chat.php`
- `favorites.php` -> редирект на `saved_chat.php`

### Группы

- создание группы;
- добавление участников по `@username` или списку username;
- чат группы;
- список групп на главной странице.

### Профиль и настройки

- имя;
- аватар;
- тема: `dark`, `light`, `system`;
- включение/выключение звука уведомлений;
- просмотр активных сессий;
- разлогинивание всех сессий, кроме текущей;
- смена PIN.

### Дополнительно

- глобальный поиск по контактам и сообщениям;
- архив чатов;
- `robots.txt` и `sitemap.xml`;
- favicon-пакет;
- страница краткой API-документации: `api/doc.php`.

## 2. Технологии и архитектура

Проект сделан без framework stack и без сборки frontend.

### Backend

- PHP
- MySQL / MariaDB
- mysqli
- сессионная авторизация

### Frontend

- HTML
- CSS
- vanilla JavaScript
- jQuery
- Bootstrap 4
- SweetAlert2
- Font Awesome

### Общая модель работы

- Каждая страница - это отдельный PHP entrypoint.
- Большинство действий из интерфейса идут в `api/*.php`.
- Ответы API в основном имеют формат:

```json
{
  "status": "success",
  "message": "OK",
  "data": {}
}
```

- Реального realtime-сокета нет.
- Интерфейс обновляется через polling: фронтенд регулярно опрашивает backend.

### Почему проект подходит для shared hosting

- нет WebSocket;
- нет Node.js;
- нет Composer-обязательств;
- нет очередей/воркеров;
- нет внешних сервисов, обязательных для запуска;
- сторонние библиотеки подключаются через CDN.

## 3. Требования к окружению

Рекомендуемая конфигурация:

- PHP 8.0+;
- PHP 8.1/8.2 - предпочтительно;
- MySQL 8.0+;
- Apache с поддержкой `.htaccess`.

### Обязательные PHP-расширения

- `mysqli`
- `mbstring`
- `json`
- `session`
- `fileinfo`

### Желательные PHP-расширения

- `gd`
  Нужен для генерации thumbnail изображений.

### Важное замечание по MySQL / MariaDB

SQL-дамп использует collation `utf8mb4_0900_ai_ci`, которая нормально работает в MySQL 8.

Если вы импортируете проект в MariaDB или старую MySQL, может понадобиться заменить collation на:

- `utf8mb4_unicode_ci`
- или `utf8mb4_general_ci`

## 4. Быстрый старт

### Вариант A: локально

1. Скопируйте проект в веб-каталог локального сервера.
2. Создайте базу данных.
3. Создайте файл `.env`.
4. Импортируйте `u3436305_messengersd.sql`.
5. Проверьте права на `uploads/` и `src/images/profile-picture/`.
6. Откройте `/login/`.
7. Введите новый `username` и создайте PIN.

### Вариант B: на хостинге

1. Залейте файлы проекта в `public_html` или нужную папку сайта.
2. Создайте MySQL-базу и пользователя.
3. Укажите данные подключения в `.env`.
4. Импортируйте SQL-дамп.
5. Убедитесь, что папки для загрузок доступны на запись.
6. Откройте сайт и войдите через `/login/`.

## 5. Настройка `.env`

Поля конфигурации собраны в [шаблоне окружения](.env.example).

В проекте нет готового `.env.example`, поэтому файл нужно создать вручную.

Минимальный пример:

```env
APP_URL=https://messengersd.ru
APP_DOMAIN=messengersd.ru
APP_DEBUG=0

DB_HOST=localhost
DB_NAME=messengersd
DB_USER=messengersd_user
DB_PASS=replace_with_your_db_pass

DB_TABLE_PREFIX=
```

### Значение переменных

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `APP_URL` | да | Базовый URL приложения |
| `APP_DOMAIN` | да | Домен приложения |
| `APP_DEBUG` | желательно | `1` для подробных ошибок, `0` для production |
| `DB_HOST` | да | Хост базы данных |
| `DB_NAME` | да | Имя базы данных |
| `DB_USER` | да | Пользователь БД |
| `DB_PASS` | да | Пароль БД |
| `DB_TABLE_PREFIX` | нет | Префикс таблиц, если нужен общий namespace |

### Как это подхватывается

- `config.php` подключает `app/env.php`;
- `loadEnvFile(__DIR__ . '/.env')` читает файл;
- значения попадают в `$_ENV` и `getenv()`.

### Защита `.env`

Корневой `.htaccess` уже содержит запрет на выдачу `.env` веб-сервером.

- реакции;

- архив;

### Как импортировать

Через phpMyAdmin:

1. Откройте нужную базу данных.
2. Перейдите в `Import`.
3. Выберите `u3436305_messengersd.sql`.
4. Импортируйте файл.

Через CLI:

```bash
mysql -u USER -p DB_NAME < u3436305_messengersd.sql
```

### Если импорт падает

Чаще всего причина в одной из проблем:

- неподдерживаемая collation;
- старая версия MySQL/MariaDB;
- уже существующие конфликтующие таблицы;
- недостаточные права пользователя БД.

## 7. Права на папки и PHP-настройки

### Папки, которым нужна запись

| Путь | Для чего нужен |
| --- | --- |
| `uploads/` | оригиналы загруженных файлов |
| `uploads/thumbs/` | миниатюры изображений |
| `src/images/profile-picture/` | аватары пользователей |
| `logs/` | необязательно, для логов загрузки файлов |

Если `logs/` не существует, отправка сообщений не ломается, но backend не сможет писать диагностический лог `logs/upload.log`.

### Рекомендуемые PHP-параметры

Так как backend допускает вложения до 50 МБ, желательно выставить:

```ini
upload_max_filesize = 50M
post_max_size = 50M
memory_limit = 128M
max_execution_time = 60
```

Если планируются крупные изображения и генерация thumbnail через GD, `memory_limit` лучше держать выше.

## 8. Развёртывание на shared hosting

Проект изначально рассчитан на shared hosting.

### Что уже учтено

- нет обязательных фоновых процессов;
- нет WebSocket;
- нет build-step;
- файлы отдаются обычным PHP/Apache;
- директория `uploads/` защищена `.htaccess`;
- корневой `.htaccess` отключает directory listing и доступ к `.env`.

### Cron-задача

Для более корректного перехода пользователей в offline желательно повесить cron на:

- `cron_mark_offline.php`

Этот скрипт переводит пользователей в offline, если `last_seen` старше 2 минут.

Рекомендуемый запуск:

- раз в минуту.

Пример:

```bash
php /path/to/project/cron_mark_offline.php
```

Если на хостинге нет CLI-доступа, можно использовать web-cron, если это допустимо политикой хостинга.

## 11. Схема данных

Ниже перечислены основные таблицы и их роль.

| Таблица | Назначение |
| --- | --- |
| `users` | пользователи, PIN, профиль, тема, last_seen, online-status |
| `messages` | личные сообщения |
| `media_files` | вложения к личным сообщениям |
| `message_reactions` | реакции на личные сообщения |
| `message_drafts` | черновики сообщений |
| `saved_messages` | сохранённые сообщения из обычных диалогов |
| `saved_chat_messages` | self-chat "Сохранённые" |
| `pinned_chats` | закреплённые чаты |
| `archived_chats` | архивированные чаты |
| `block_users` | блокировки пользователей |
| `user_typing` | индикатор "печатает..." |
| `user_sessions` | активные пользовательские сессии |
| `groups` | группы |
| `group_members` | участники групп |
| `group_messages` | сообщения в группах |

### Особенно важные различия

#### `saved_messages` и `saved_chat_messages`

- `saved_messages` хранит ссылки на уже существующие сообщения из таблицы `messages`.
- `saved_chat_messages` хранит отдельные самостоятельные записи self-chat.

#### `user_sessions`

Таблица используется не только как журнал входов. Она участвует в инвалидировании сессий:

- при "разлогинить все, кроме текущей" у чужих сессий ставится `is_active = 0`;
- при следующем запросе `Database` проверяет `user_sessions`;
- если сессия помечена как неактивная, backend уничтожает её.

## 12. Пользовательские сценарии

### Первый вход

1. Пользователь открывает `/login/`.
2. Вводит username.
3. `api/auth/start.php` проверяет, существует ли пользователь и задан ли PIN.
4. Если пользователь новый, UI переводит на шаг создания PIN.
5. После сохранения PIN пользователь сразу авторизуется.

### Обычный вход

1. Пользователь вводит username.
2. Backend отвечает, что PIN уже есть.
3. UI показывает поле ввода PIN.
4. После успешной проверки создаётся сессия и запись в `user_sessions`.

### Работа с личным чатом

1. Главная страница загружает список контактов.
2. При открытии `chat.php?id=...` выполняется polling сообщений.
3. Непрочитанные сообщения помечаются как `read`.
4. Сообщения можно редактировать, удалять, сохранять, архивировать чат, закреплять чат.

### Работа с "Сохранёнными"

1. Пользователь открывает `saved_chat.php`.
2. Страница загружает записи из `saved_chat_messages`.
3. Отправка сообщения сохраняет новую запись, привязанную к текущему `user_id`.

### Работа с группами

1. На `groups.php` пользователь задаёт название группы.
2. Можно добавить участников по username.
3. Создаётся запись в `groups` и участники в `group_members`.
4. `group_chat.php` показывает переписку и отправляет сообщения в `group_messages`.

## 13. API и backend endpoints

Ниже перечислены основные endpoints, которые реально используются текущим интерфейсом.

### Общий формат

- большинство API лежат в `api/`;
- почти все возвращают JSON;
- авторизованные endpoints требуют активную сессию.

### 13.1 Авторизация

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `POST` | `api/auth/start.php` | определить следующий шаг: создать PIN или ввести PIN |
| `POST` | `api/auth/set_pin.php` | создать пользователя или сохранить PIN для существующего username |
| `POST` | `api/auth/login_pin.php` | вход по PIN |
| `POST` | `api/auth/change_pin.php` | смена PIN |
| `POST` | `api/auth/logout.php` | выход и деактивация текущей сессии |
| `GET/SESSION` | `api/auth/check_login.php` | проверить, залогинен ли пользователь |

### 13.2 Профиль и настройки

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `GET` | `api/fetch_profile.php` | получить профиль текущего пользователя |
| `POST` | `api/fetch_profile.php` | обновить имя, аватар, тему, звук |
| `GET` | `api/sessions.php` | список активных сессий |
| `POST` | `api/sessions.php` | logout других сессий или logout конкретной сессии |

### 13.3 Личные чаты

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `GET` | `api/fetch_contacts.php` | список контактов для главной страницы |

| `POST` | `api/send_message.php` | отправка сообщения и вложений |
| `POST` | `api/edit_message.php` | редактирование сообщения |
| `POST` | `api/delete_message.php` | удаление сообщения |
| `POST` | `api/clear_messages.php` | очистка переписки |

### 13.5 Поиск, статусы, typing, блокировки

| Метод | Endpoint | Назначение |
| --- | --- | --- |

## 14. Как устроено обновление данных

Проект обновляет состояние не через websocket, а через polling.

### Текущие интервалы

- `index.php`: список чатов обновляется примерно раз в 1 секунду;
- `index.php`: кэш групп обновляется раз в 5 секунд;
- `archived.php`: список архива обновляется примерно раз в 1.5 секунды;
- `chat.php`: сообщения в личном чате обновляются примерно раз в 1 секунду;
- `chat.php`: typing-статус проверяется примерно раз в 2 секунды;
- `group_chat.php`: сообщения группы обновляются примерно раз в 1.2 секунды;
- `saved_chat.php`: self-chat сейчас обновляется при загрузке страницы и после отправки сообщения.

### Плюсы такого подхода

- работает на простом хостинге;
- проще деплой;
- проще backend;
- легче отлаживать.

### Минусы

- выше нагрузка на сервер при большом числе пользователей;
- realtime не мгновенный, а с задержкой polling-интервала;
- много мелких HTTP-запросов.

## 15. Безопасность

В проект уже заложены несколько базовых мер безопасности.

### Что уже сделано

- PIN хранится через `password_hash`;
- выдача файлов идёт через `download.php` с проверкой прав доступа;
- `.env` закрыт `.htaccess`;
- в `uploads/` запрещено выполнение PHP и похожих скриптов;
- запросы к БД идут через prepared statements;
- есть ограничение на формат username;
- есть лимит на PIN и блокировка после ряда ошибок;
- доступ к чужим файлам проверяется через `messages` и `media_files`;
- неактивные сессии убиваются через таблицу `user_sessions`.

### Что стоит помнить

- при `APP_DEBUG=1` backend может отдавать более подробные ошибки;
- для production держите `APP_DEBUG=0`;
- если переносите проект на Nginx, запреты из `.htaccess` нужно повторить в конфиге Nginx;
- если планируется публичное использование, стоит добавить CSRF-защиту и ограничение rate-limit на критичные endpoints.

## 16. Важные заметки для разработчика

### 1. Используйте `startAppSession()`

Для новых entrypoint-файлов предпочтителен такой шаблон:

```php
require_once __DIR__ . '/app/session.php';
startAppSession();
```

Это важно, потому что `app/session.php`:

- задаёт cookie lifetime;
- выставляет `SameSite`;
- делает поведение сессии более предсказуемым на shared hosting.

### 2. `Database` делает больше, чем просто коннект

Конструктор `Database` в `config.php`:

- проверяет, существует ли текущий пользователь;
- обновляет `last_seen` и `is_online`;
- поддерживает `user_sessions`;
- может уничтожить сессию, если `user_sessions.is_active = 0`.

Это значит, что создание объекта `Database` имеет side-effect.

### 3. Используйте `t()` для таблиц

Если добавляете SQL вручную, используйте:

```php
$db->t('messages')
```

Это позволяет поддерживать `DB_TABLE_PREFIX`.

### 4. Источник структуры БД - SQL-дамп

В проекте нет мигратора. Если вы добавили новую таблицу или поле:

1. обновите PHP-код;
2. обновите `u3436305_messengersd.sql`;
3. только после этого считайте изменение завершённым.

### 5. Frontend завязан на JSON-формат

Не ломайте без необходимости поля:

- `status`
- `message`
- `data`

На этом завязано много JS-обработчиков в страницах.

### 6. Проект без build-step

Это плюс, но и ограничение:

- нет модульной сборки;
- нет TypeScript;
- нет bundler;
- нет package manager как обязательной части запуска.

Поэтому изменения в JS/CSS делаются напрямую в файлах проекта.

## 17. Частые проблемы и диагностика

### Ошибка импорта SQL из-за collation

Проблема:

- база не понимает `utf8mb4_0900_ai_ci`.

Что делать:

- заменить collation на `utf8mb4_unicode_ci`;
- либо использовать MySQL 8.

### Не загружаются вложения

Проверьте:

- `upload_max_filesize`;
- `post_max_size`;
- права на `uploads/`;
- доступность `fileinfo`;
- размер файла не больше 50 МБ.

### Не создаются thumbnail изображений

Причина:

- отсутствует GD.

Что будет:

- оригинал файла всё равно сохранится;
- thumbnail может не появиться.

### Не работают аватары

Проверьте:

- права на `src/images/profile-picture/`;
- допустимые форматы: `jpg`, `jpeg`, `png`, `gif`.

### "Разлогинить все сессии" как будто не сработало

Это поведение частично отложенное.

Что происходит:

- текущий backend ставит другим сессиям `is_active = 0`;
- фактический вылет из этих сессий случится на их следующем запросе.

### Пустой self-chat или ошибка на `saved_chat.php`

Проверьте:

- импортирована ли таблица `saved_chat_messages`;
- не удалили ли вы endpoints `api/saved_chat_fetch.php` и `api/saved_chat_send.php`;
- что `saved.php` и `favorites.php` не переопределены сторонним кодом.

### Нет логов загрузки файлов

По умолчанию backend пытается писать в:

- `logs/upload.log`

Если папки `logs/` нет, приложение не обязано падать, но логирования не будет.

### После правок в интерфейсе браузер показывает старую версию

Сначала попробуйте:

- `Ctrl+F5`
- или очистку кэша браузера

Особенно это заметно после изменения:

- `src/css/style.css`
- inline JS в `index.php`, `chat.php`, `saved_chat.php`
